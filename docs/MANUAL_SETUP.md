# Manual Setup — Follow Sequentially

This document lists the work you do manually and the work delegated to the coding agent.

## Step 1 — Install local tools
Install:
1. Git
2. Node.js LTS (use the current supported LTS)
3. pnpm (`npm install -g pnpm`)
4. Docker Desktop
5. Android Studio (Android SDK + emulator) or use your Android phone with Expo Go for early testing
6. VS Code, Cursor or Antigravity

Verify:
```bash
node -v
npm -v
pnpm -v
git --version
docker --version
```

## Step 2 — Create the project repository
1. Create a private GitHub repository named `myday`.
2. Download and extract this starter ZIP.
3. Copy the extracted contents into the repository root.
4. Open that folder in Cursor/Antigravity.
5. Make the first Git commit containing only docs/config starter files.

```bash
git init
git add .
git commit -m "chore: add MyDay project specification"
```

## Step 3 — Start local PostgreSQL
From the repository root:
```bash
docker compose up -d db
docker compose ps
```
The starter `docker-compose.yml` created by the agent should expose local port 5432. Suggested local DB:
- database: `myday`
- username: `myday`
- password: local-only development password
- host: `localhost`
- port: `5432`

Do not expose port 5432 publicly. Do not reuse the local password in production.

## Step 4 — Create Neon cloud database (can wait until deployment)
1. Create a Neon account.
2. Create a project named `myday`.
3. Select a region close to your expected users.
4. Create a database/role if not created automatically.
5. Copy the connection string into a password manager.
6. Add it only to the API host's server-side environment as `DATABASE_URL`.
7. Keep a direct connection string for migrations if the provider provides one; use pooled connection for serverless runtime when recommended.
8. Never put the database URL in an Expo public variable.

Do not connect Neon before local migrations work.

## Step 5 — Ask the agent to scaffold
Open `PROMPTS.md` and run Prompt 0, then Prompt 1. Review the plan before allowing implementation. Agent should create:
- `apps/client` Expo Router universal app
- `apps/api` Fastify API
- `packages/contracts`, `packages/core`, `packages/db`
- pnpm workspace and scripts

## Step 6 — Configure environment
The agent should create:
- `apps/api/.env` or a root env loaded only by API
- `apps/client/.env` only for public client settings

Use `.env.example` as a template. Typical API variables:
```env
NODE_ENV=development
PORT=4000
DATABASE_URL=postgresql://myday:LOCAL_PASSWORD@localhost:5432/myday
AUTH_SECRET=generate_a_long_random_secret
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
APP_WEB_URL=http://localhost:8081
API_BASE_URL=http://localhost:4000
```
Expo public variable (only if needed):
```env
EXPO_PUBLIC_API_URL=http://localhost:4000
```
For a physical Android phone, `localhost` points to the phone itself, not your computer. Use your computer's LAN IP for local API testing, and ensure phone/computer are on the same trusted Wi-Fi. Do not expose your dev API to public internet.

## Step 7 — Connect Drizzle ORM
The agent implements `packages/db` and `drizzle.config.ts` based on current Drizzle docs. Expected workflow:
```bash
pnpm install
pnpm db:generate
pnpm db:migrate
pnpm db:studio
```
Actual script names may be adjusted by the agent; it must document them in README. Use migrations as the source of truth. Do not use schema push as the production migration strategy.

## Step 8 — Google OAuth setup (only when auth phase starts)
1. Open Google Cloud Console.
2. Create a project.
3. Configure OAuth consent screen / Google Auth Platform.
4. Add your test email while app is in testing mode.
5. Create OAuth client credentials appropriate to the Better Auth + Expo flow.
6. Configure exact redirect/callback URLs generated by the implementation.
7. Put client ID/secret in API server env only.
8. Test web sign-in and Android sign-in separately.

Important:
- Do not guess redirect URLs; copy exact callback URLs from the auth library/app logs.
- Google sign-in only grants identity. Drive/Calendar permissions are separate later.
- Publishing an OAuth app may require verification depending on scopes and audience.

## Step 9 — Run app locally
The agent should document exact commands. Typical development:
```bash
pnpm install
pnpm dev:api
pnpm dev:client
```
Open Expo web URL in browser or scan QR with Expo Go. For Android physical device, configure API URL to computer LAN IP. Test API health endpoint and create a test entry.

## Step 10 — Test both platforms
Checklist:
- [ ] Android app starts
- [ ] Web app starts
- [ ] Login works on both
- [ ] Create/edit/delete diary entry
- [ ] Refresh and data persists
- [ ] User isolation works
- [ ] Local DB migration works
- [ ] Offline draft works on both (when phase arrives)
- [ ] Export works

## Step 11 — Connect Neon
Only after local migrations and tests pass:
1. Set Neon `DATABASE_URL` in API deployment environment.
2. Run committed Drizzle migrations against Neon using the documented migration command.
3. Verify API health/readiness.
4. Never run destructive schema changes against production without backup and review.

## Step 12 — Deployment choices
- Web: choose a host that supports Expo web static output or the configured server rendering mode.
- API: choose a Node.js host that supports Fastify and your chosen free tier.
- Database: Neon.
- Mobile: EAS Build for Android.
Free-tier terms, sleep/inactivity, build minutes, bandwidth and storage limits change. Verify current terms before committing to a provider.
Nginx is only needed if you rent/manage a server and want a reverse proxy. It is not required for Neon.

## Step 13 — Google Play Store (later)
1. Create Google Play Console developer account.
2. Complete identity/account requirements and any required testing track.
3. Generate Android production build using EAS Build.
4. Prepare app icon, screenshots, description and privacy policy.
5. Complete Data safety and content declarations accurately.
6. Upload AAB to internal testing.
7. Test install/update/login/data deletion.
8. Submit for review.
Expo can build/submit the binary but cannot bypass Play Console requirements or guarantee approval.

## Manual vs agent responsibilities

You do manually:
- Install tools
- Create GitHub, Neon and Google Cloud accounts
- Create OAuth credentials and configure redirect URLs
- Keep secrets safe and set deployment environment variables
- Approve Git commits, migrations and production deploys
- Create Play Console account and submit the app

The coding agent does:
- Scaffold repo and app code
- Implement Drizzle schema/migrations
- Build API and Expo screens
- Implement tests and documentation
- Integrate providers after you supply credentials
- Prepare deployment/build commands

Never paste real secrets into public chats or commit them to Git.
